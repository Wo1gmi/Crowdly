# Crowdly Workspace

Рабочий MVP платформы симуляции спроса и экономики коммерческих объектов. Реализован по презентации **Crowdly_16.11_final.pdf** (слайды 1, 3–7 и 9). Это интерактивное аналитическое приложение, не лендинг.

## Запуск

Требуется Node.js 20.19+ или 22+.

```sh
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite (по умолчанию http://127.0.0.1:5173).

```sh
npm run check   # модельные тесты и production-сборка
npm run preview # просмотр production-сборки
```

## Что работает

- Создание, переключение и удаление независимых проектов; RUB, USD или AED без автоматической конвертации.
- CRUD проектируемых объектов, действующих точек сети и конкурентов. Координаты, формат, площадь, цены, вместимость, длительность визита, режим работы, затраты и инвестиции.
- CRUD групп аудитории: численность, расположение, бюджет, частота посещений категории, чувствительность к цене и времени в пути.
- Сценарии открытия, изменения формата/площади/цены/локации, вместимости и стрессов по спросу и затратам. Создание, сохранение, дублирование, редактирование, сравнение и удаление.
- Месячное распределение потенциального спроса между объектами и внешней альтернативой. Ограничение вместимости, сезонность, рост и выход на загрузку.
- Отдельный расчёт прироста сети с учётом потерь действующих точек.
- Четыре редактируемые категории состава пространства; аренда за м², занятость площади и процент с оборота.
- Прямые продажи + дополнительные услуги либо доход владельца от аренды + оборота.
- Месячные денежные потоки, NPV, эффективная годовая IRR, ROI и срок окупаемости. Переключение «объект / сеть».
- CSV-импорт месячных посещений/продаж с валидацией, предпросмотром и подтверждением замены истории. CSV-экспорты объектов, истории, прогноза и сравнения.
- Оценка одного коэффициента масштаба спроса по истории действующих объектов.
- Отчёт текущего сценария, печать/сохранение PDF средствами браузера.
- Локальное сохранение, JSON-резервная копия и восстановление с валидацией.
- Поиск по проектам, объектам и сценариям. Адаптивная навигация, формы с подписями и модальные окна с удержанием фокуса.

При первом запуске используется **синтетический демонстрационный проект**. Его значения не являются данными Термолэнда или другой компании и не подтверждают точность прогнозирования.

## GitHub Pages

Удалённый репозиторий: `git@github.com:Wo1gmi/Crowdly.git`.

Workflow `.github/workflows/pages.yml` запускает `npm ci`, тесты, сборку и публикует `dist` после push в `main`. В GitHub нужно включить **Settings → Pages → Source: GitHub Actions**. Для приватного репозитория доступность Pages зависит от тарифа GitHub.

Приложение использует hash-навигацию (`#/` не требуется: `#dashboard`, `#simulator` и т. д.), поэтому переходы и обновление страниц работают на статическом хостинге. `base: './'` позволяет размещать сборку в `/Crowdly/` без абсолютных путей к ассетам.

В production сервер Node.js не требуется. На сервер отправляются только статические файлы приложения; данные проекта остаются в LocalStorage конкретного браузера. GitHub Pages не обеспечивает серверные аккаунты или совместный доступ.

## Архитектура

```text
src/
  components/     UI, диаграммы, схема координат
  data/           фабрики сущностей и синтетический seed
  domain/         чистые модели спроса, симуляции, финансов, валидация
  pages/          рабочие разделы
  services/       хранение и CSV
  App.jsx         координация проекта, навигации, сценария
  styles.css      адаптивная система оформления
public/           статические ассеты
scripts/          вспомогательные скрипты
tests/            node:test без браузерных зависимостей
docs/             требования, математика, ограничения и план расширения
```

Модель не зависит от React, DOM, LocalStorage или API. Основной контракт: `simulate(project, scenario) → SimulationResult`. Структура результата включает месячные ряды, результаты объектов, годовые агрегаты, отдельные денежные потоки объекта/сети и финансовые показатели. Для будущего API или worker-процесса можно передавать те же сериализуемые DTO и сохранять форму ответа. Асинхронный провайдер потребует адаптации управления загрузкой на уровне приложения.

Репозиторий хранения отделён в `services/storage.js`. Его можно заменить серверным repository, сохранив валидацию сущностей. Мультиарендность и доступы должны контролироваться на будущем backend, а не в браузере.

## Важные ограничения

Модель детерминированная; параметры поведения задаёт пользователь. Автоматического обучения эластичности, внешних API, причинного доказательства влияния цен, вероятностных интервалов и точности на реальных клиентах здесь нет. CSV-калибровка оценивает только масштаб потенциального спроса. Открытые интеграции из презентации (Росстат, Esri, OSM, Overture, ROLLER) представлены локальным вводом и импортом, а не имитирующими подключение кнопками.
